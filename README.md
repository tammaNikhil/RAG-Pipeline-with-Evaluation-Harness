# RAG Pipeline with Evaluation Harness

An end-to-end Retrieval-Augmented Generation (RAG) system: ingest documents,
chunk and embed them into a vector store, retrieve relevant context for a
query, generate a grounded answer with an LLM, and score the whole pipeline
against a hand-built golden test set.

## Architecture

```
data/raw/*.txt
      │
      ▼
  ingest.py  ──────────────►  parses files into {content, metadata}
      │                       (sorted file order → deterministic chunk IDs)
      ▼
  chunk.py   ──────────────►  fixed-size word chunks, w/ overlap
      │                       data/processed/chunks.jsonl
      ▼
  embed.py   ──────────────►  sentence-transformers (all-MiniLM-L6-v2)
      │                       → Chroma vector DB (cosine distance)
      ▼
  chroma_db/
      │
      ▼
  retrieve.py ─────────────►  embed query → top-k nearest chunks
      │
      ▼
  generate.py ─────────────►  prompt LLM (Gemini) with retrieved context
      │                       → grounded, cited answer
      ▼
  evaluate.py ─────────────►  runs golden_qa.json through the pipeline,
                              scores retrieval (Recall@k, Precision@k, MRR)
                              and generation (Faithfulness, Relevance)
                              → eval/results/summary.json
```

## Quickstart

```bash
# Install dependencies
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# Set your Gemini API key (from Google AI Studio)
export GEMINI_API_KEY="your-key-here"

# Run tests
.venv/bin/pytest src/test_pipeline.py

# 1. Ingest & chunk documents
.venv/bin/python src/chunk.py

# 2. Embed & build vector index
.venv/bin/python src/embed.py

# 3. Run evaluation harness (retrieval + generation)
.venv/bin/python src/evaluate.py
```

Results land in `eval/results/summary.json` and `eval/results/retrieval_metrics.csv`.

## Project layout

```
config.yaml              # all tunable pipeline settings
data/raw/                # source documents (.txt, .pdf, .docx, .html)
data/processed/          # chunks.jsonl — chunked output
chroma_db/                # persisted vector index
eval/golden_qa.json       # hand-labeled question set with expected chunks/answers
eval/results/             # evaluation output (generated by evaluate.py)
src/
  ingest.py               # file parsing → {content, metadata}
  chunk.py                # fixed-size word chunking with overlap
  embed.py                # embedding + Chroma indexing
  retrieve.py              # query embedding + nearest-neighbor search
  generate.py              # prompt construction + LLM call (Gemini/OpenAI/mock)
  evaluate.py              # golden-set evaluation harness
  service.py                # optional FastAPI wrapper
  test_pipeline.py          # unit tests
```

## Configuration (`config.yaml`)

| Setting | Current value | Notes |
|---|---|---|
| `chunking.chunk_size` | 90 words | tuned for this small corpus; see docs for the tradeoff |
| `chunking.chunk_overlap` | 20 words | ~22%, keeps context across boundaries |
| `embedding.model_name` | `all-MiniLM-L6-v2` | fast, local, 384-dim |
| `retrieval.top_k` | 3 | precision/recall tradeoff — see PROJECT_EXPLAINED.pdf |
| `generation.model_name` | `gemini-3.5-flash-lite` | requires `GEMINI_API_KEY` env var |

## Generator behavior

`generate.py` checks for credentials in this order and falls back gracefully:
1. `GEMINI_API_KEY` set → calls Gemini (`google-genai` SDK)
2. else `OPENAI_API_KEY` set → calls OpenAI
3. else → deterministic mock (echoes the top retrieved chunk; useful for
   testing the pipeline plumbing without any API cost, but not a real answer)

## Evaluation metrics

- **Recall@k** — of the chunks that *should* have been retrieved, what
  fraction were in the top-k results?
- **Precision@k** — of the top-k results returned, what fraction were
  actually relevant?
- **MRR (Mean Reciprocal Rank)** — how high up was the first relevant result?
- **Faithfulness** — does the generated answer stick to the retrieved
  context (vs. hallucinating or ignoring it)?
- **Relevance** — word-overlap (Jaccard) between the generated answer and
  the expected answer. A blunt but deterministic proxy — a good answer
  phrased differently from `expected_answer` can score low here even when
  it's correct, so read it alongside `faithfulness`, not in isolation.
